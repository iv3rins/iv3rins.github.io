# 任务目标
你是一个资深全栈游戏开发者。请基于以下规则，开发一款【纯前端、无后端、基于 PeerJS (WebRTC) 的 P2P 多人对战卡牌游戏】。游戏为 SPA（单页面应用），UI 需根据状态动态渲染。

# 技术架构 (Host-Client 状态同步)
* 依赖：纯 HTML/CSS/JS + PeerJS。
* 联机逻辑：房主 (Host) 负责运行游戏引擎、处理所有人发来的 Action 请求、计算结果，并广播全局 State；客户端 (Client) 只负责发送 Action、接收 State 并动态渲染 UI（禁止在客户端本地计算伤害）。
* 视图路由：Home（建房/加入） -> Waiting（大厅/聊天） -> Game（战斗） / Spectator（观战） -> Result（结算）。
* 部署环境：项目托管在 GitHub Pages (纯静态 HTTPS 环境)。
* 网络联机要求 (极其重要)：
  1. 必须直接使用 PeerJS 的默认公共信令服务器（即无参实例化 `new Peer()` 或仅指定 ID，千万不要让我在本地起 Express/Socket.io 服务器）。
  2. 房主断线处理：因为没有实体服务器，一旦房主（Host）断开连接或刷新页面，必须立刻通过 PeerJS 的 `close` 或 `error` 事件通知所有客户端，并利用 UI 弹窗提示“房主已断开，房间解散”，然后将客户端退回 Home 主页。
  3. 客户端断线处理：如果某个 Client 掉线，房主引擎需将其标记为“已淘汰(断线)”，并广播新 State。

# 核心游戏规则
* 卡牌堆：4人1副牌，每多4人加1副。弃牌堆耗尽洗牌。手牌上限7张。无回合自然摸牌。
* 角色系统：J、Q、K不入牌堆，作为角色牌。每人随机发 J(30血), Q(40血), K(50血) 各一张，花色随机。1张首发，2张备战。死后切人，3死淘汰。
* 基础出牌：合法牌型为1张、3张（同花色）、5张（同花色）。伤害/护盾/回血量 = 牌面数字总和。
* 万能牌(A)：可随牌打出，指定点数和花色。不计入打出数量。每次出牌最多带1张A。
* 特殊牌(Joker)：不能普攻。单出1张 = 满血复活指定濒死角色；出2张(需拥有全场所有Joker) = 无视血盾直接斩杀指定玩家。
* 花色特效：
  * ♦方块：伤害结算后，从自己开始逆时针每人摸1张，累计摸满5张停（满手牌跳过）。
  * ♣梅花：自己获得等同于牌面数字的护盾（护盾优先抗伤）。
  * ♥红桃：吸血，恢复等同于实际造成伤害的血量。
  * ♠黑桃：最终伤害翻倍。
* 花色免疫：攻击牌花色与目标角色花色相同时触发。打同色♦(不触发摸牌)，打同色♣(无视目标护盾)，打同色♥(攻击者不回血)，打同色♠(取消双倍伤害)。
* 补牌触发：打出后，若手牌为0，或剩余手牌全是Joker，立即补3张。
* 胜负条件：存活到最后的1人获胜。

# UI/UX 动态渲染规范
* 风格：极简、可爱、卡通。主题色粉色(#ffb6c1)，血条红色(#ff7675)，护盾蓝色(#74b9ff)。
* 布局要求：
  * 对局UI：顶部平铺对手（包含角色Emoji、花色/数值、血条、护盾条、手牌数）；左下角为玩家自己；右下角为手牌区（平铺层叠效果，点击凸起）；右侧停靠聊天框；中间为出牌动作区及 30秒倒计时条。
  * 观战UI：玩家淘汰后自动进入，手牌与操作区隐藏，自身卡片置灰并增加哭泣特效。
* 动画：选中卡牌的上浮动画、出牌时的残影飞行动画、受伤抖动。

# 你的产出要求
请一步步思考，然后一次性输出以下完整代码文件（必须包含详尽中文注释）：
1. `index.html`：整合所有 CSS 样式（包含动画）和 SPA 视图容器结构。
2. `gameEngine.js`：纯游戏规则计算逻辑，不能包含DOM操作。
3. `p2pManager.js`：基于 PeerJS 的联机、聊天与广播模块。
4. `app.js`：负责实例化网络与引擎、劫持 UI 交互、处理 Host-Client 数据流，以及编写基于 State 的核心 UI 动态渲染函数 `renderState()`。
