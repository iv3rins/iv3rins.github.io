# 安全与性能基线

## 安全

- 服务器权威：客户端不能提交伤害值、牌面结果、回合号或赢家。
- 每条消息先检查字节长度，再 JSON 解析，再 Zod 校验，再权限校验。
- 单连接默认每秒 20 条、突发 40 条；聊天单独限制。
- 玩家名最长 24 字符，聊天最长 200 字符，头像只接受受控标识或 HTTPS URL。
- 重连令牌是高熵随机值，仅存内存；日志中必须脱敏。
- WebSocket 生产环境只通过 WSS；Nginx 限制 Origin 和请求体。
- SQLite 使用 prepared statement；数据库文件权限 640。
- JWT 只用于未来账户 API，不用于房间内每个动作，避免热路径重复验签。

## 性能

- 房间状态驻留内存；数据库只写比赛结果和排行榜。
- 状态更新按玩家生成最小公开视图；对手手牌不复制卡牌对象。
- 广播按 revision 合并；同一事件循环内最多发送一次最终状态。
- 手牌和日志限制长度，避免状态无限增长。
- UI 使用事件代理和 `DocumentFragment`，不为每张牌重复注册永久监听器。
- 初始单进程。只有 CPU 使用持续超过 70% 且房间可外置后，才考虑多进程。

## 入门 KVM 默认值

- Node 堆上限：512 MiB。
- PM2 `max_memory_restart`：700 MiB。
- 最大连接：800；最大房间：200；每房间最多 4 人。
- Nginx WebSocket 空闲超时：75 秒；应用心跳：15 秒。
- SQLite WAL；比赛结束事务写入。
